# Хантайшир Эко Блок — Google Sheets үнийн санал ба дилерийн хүсэлтийн бүртгэл

Зорилтот хүснэгт:
https://docs.google.com/spreadsheets/d/1q8awc7qZYLhoPkWOfvptJAzcY25fNLUaJgFNdrJAquw/edit?gid=0

**Одоо байгаа gid=0 табыг болон өмнө бүртгэгдсэн үнийн хүсэлтүүдийг өөрчлөхгүй.** Скрипт нь тусдаа **«Веб үнийн хүсэлт»** болон **«Гэрээт борлуулагчийн хүсэлт»** таб ашиглана.

## Холбох алхам

1. Энэ Google Sheets файлыг **засварлах эрхтэй Google бүртгэлээр** нээнэ.
2. **Extensions → Apps Script**-ийг нээгээд GitHub дахь [Code.gs](./Code.gs) кодыг хуулж, шинэ төслийн Code.gs кодыг солиод Save дарна.
3. **setup** функцийг сонгож **Run** дарна. Google эрхийн хүсэлтийг баталгаажуулж, Sheets-д «Веб үнийн хүсэлт» таб нэмэгдсэн эсэхийг шалгана.
4. **Deploy → New deployment → Web app**, Execute as **Me**, Who has access **Anyone** гэж сонгоно. Deploy дарна.
5. Шинэ Web app URL-ийг хуулна. Хэлбэр нь: https://script.google.com/macros/s/....../exec
6. GitHub index.html дахь SITE.sheetWebhook гэсэн тохиргооны хоосон мөрөнд энэ URL-ийг оруулаад commit/merge хийнэ. URL оруулахаас өмнө автомат илгээлт идэвхжихгүй.

## Яаж ажиллах вэ?

Хэрэглэгч нэр, утас, төслийн байршил, блокийн хэмжээ, м³ оруулж зөвшөөрлийн тэмдэглэгээ хийсний дараа хүсэлт Apps Script рүү илгээгдэнэ. Скрипт «Веб үнийн хүсэлт» табд огноо, хүсэлтийн дугаар, төлөв, харилцагч, утас, байршил, төрөл, задаргаа, м³, ширхэг, нэгж үнэ, нийт үнэ, имэйл, тайлбар, UTM болон зөвшөөрлийг хадгална.

Сайт зөвхөн Google-ээс хүсэлт хадгалагдсаныг баталгаажуулсан хариу хүлээн авсан үед амжилттай гэж харуулна. Хариу ирээгүй бол давхар бүртгэл үүсгэхээс сэргийлж Sheets-ийг шалгахыг зөвлөнө.

## Туршилт (заавал)

1. Web app /exec URL-ийг нээгээд «Сервис ажиллаж байна» гэсэн мессеж харагдахыг шалгана.
2. Веб формд зохиомол тестийн мэдээлэл бөглөж илгээнэ.
3. Sheet-д шинэ мөр бүртгэгдсэнийг шалгана.
4. Сайт дээр амжилттай гэсэн хариу гарч байгааг нягтална.
5. Алдаа гарвал Apps Script → Executions хэсгийг шалгана.

## Аюулгүй байдал

- Google Sheet-ээ **нийтэд Editor эрхтэй** болгож болохгүй.
- Скрипт нь хүсэлт хадгалахын тулд эзэмшигчийн эрхээр ажиллана; Apps Script Web app нь Anyone эрхтэй тул спам эрсдэлтэй. Траффик өсөхөд CAPTCHA болон rate-limit нэмэх хэрэгтэй.
- Бодит нууц үг, токеныг GitHub-д огт оруулахгүй.
- Бодит хэрэглэгчийн мэдээллийг нээлттэй тестэд ашиглахгүй.
- Үнэ, татвар болон подоны нөхцөлийг борлуулалтын баг албан ёсоор баталгаажуулна.

**Анхаар:** Google бүртгэлийн эзэмшигч Web App-ийг deploy хийх хүртэл код бэлэн байсан ч бодит автомат бүртгэл ажиллахгүй.

## 2026.11.02 — Гэрээт борлуулагчийн шинэ бүртгэлийг идэвхжүүлэх

**Хэрэв үнийн хүсэлтийн Web App аль хэдийн ажиллаж байвал шинэ Deployment бүү үүсгэ.**
Хуучин `/exec` URL-ээ хадгалахыг зөвлөж байна.

1. Google Sheets → **Extensions → Apps Script** нээнэ.
2. GitHub дахь шинэ [Code.gs](./Code.gs)-г **бүтнээр нь** хуулж одоогийн `Code.gs`-тэй солиод **Save** дарна. Хуучныг хэсэгчлэн нэмэхгүй.
3. Functions цэсээс **setup** сонгож **Run** дарна. Шинэ «Гэрээт борлуулагчийн хүсэлт» таб нэмэгдсэнийг шалгана. Одоо байгаа «Веб үнийн хүсэлт» табын өгөгдөл үлдэнэ.
4. Apps Script → **Deploy → Manage deployments → одоогийн Web app → Edit (харандаа) → Version: New version → Deploy**.
5. Хуучин `/exec` URL өөрчлөгдөөгүй эсэхийг шалгана.
6. GitHub вебсайтын `index.html` доторх `dealerBackendReady:false` утгыг `true` болгосны дараа дилерийн хүсэлт тусдаа табд автоматаар бүртгэгдэнэ. Энэ идэвхжүүлэлтийг backend шинэчлэгдсэний дараа л хийнэ.
7. Зохиомол тестийн мэдээллээр нэг **үнийн хүсэлт**, нэг **дилерийн хүсэлт** илгээж тус тусын табд зөв бүртгэгдсэнийг шалгана.

### Дилерийн хүсэлтийн багана
Огноо, хүсэлтийн ID, төлөв, байгууллага, холбоо барих хүн, утас, байршил, имэйл, бизнесийн чиглэл, тайлбар, эх сурвалж, UTM, зөвшөөрөл.

**Идэвхжүүлэхээс өмнө:** Сайтын дилерийн шинэ форм нь тусдаа харагддаг, мэдээллээ хуулж авах боломжтой боловч **Google Sheets-д автоматаар хадгалагдахгүй**. Ийм үед амжилттай бүртгэсэн гэж харуулахгүй.


## Борлуулалтын баталгаажуулалт → албан PDF → имэйл

Код GitHub-д бэлтгэгдсэн. Apps Script-д суулгаж, эзэмшигч Google эрхийг зөвшөөрсний дараа энэ урсгал ажиллана. GitHub-д commit хийх нь Apps Script-ийг автоматаар шинэчлэхгүй.

### Одоо байгаа төсөлд суулгах
1. Дээрх хүснэгтээс **Extensions → Apps Script** нээнэ. Одоо ажиллаж буй `Code.gs`-ийн нөөц хувилбарыг аваад энэ хавтасны шинэ `Code.gs`-г бүтнээр солино. Өмнөх хэсгүүд дээр давхар нэмж болохгүй.
2. Хүснэгтийн эзэмшигч **setupSalesWorkflow** функцийг нэг удаа ажиллуулна. Энэ нь эзэмшигчийг анхны батлах хэрэглэгчээр бүртгэж, **Албан үнийн санал** таб болон хоёр хувийн Drive хавтас үүсгэнэ. Google-ийн Sheets, Drive, имэйл илгээх эрхийн хүсэлтийг эзэмшигч өөрөө зөвшөөрнө.
3. Хүснэгтийг дахин нээхэд **Үнийн санал** цэс гарна. Хэрэв скрипт хүснэгтэд холбогдоогүй standalone төсөл бол энэ кодыг хүснэгтийн Extensions цэснээс нээсэн bound төсөлд байрлуулах шаардлагатай.
4. Нэмэлт борлуулалтын ажилтан оруулах бол төсөл эзэмшигч Script Properties дахь **KH_SALES_APPROVERS** утгад баталгаажуулсан Google имэйлүүдийг таслалаар тусгаарлан оруулж, шаардлагатай хүснэгтийн засварлах эрхийг тусад нь тохируулна. Нэрээр нь хаяг тааж нэмэхгүй.
5. Зөвхөн дотоод Sheets цэс ашигладаг тул одоо ажиллаж буй нийтийн `/exec` URL-ийг солих шаардлагагүй. Нийтийн lead receiver өөрчлөгдөөгүй; түүний хуучин deployment ажиллана. Шинэ хувилбарыг deploy хийх тохиолдолд хуучин deployment-ийг **New version**-оор шинэчилж URL-ээ хадгална.

### Борлуулалтын ажилтны үйлдэл
1. **Веб үнийн хүсэлт** табын нэг хүсэлтийн мөр сонгоно.
2. **Үнийн санал → 2. Сонгосон хүсэлтээс санал бэлтгэх**. Нэг хүсэлтээс давхар draft үүсгэхгүй.
3. Шинэ табын A–P баганыг хянана: үнэ, төгрөгөөрх хөнгөлөлт, бодит подоны тоо, нэг подоны барьцаа, НӨАТ-ын нөхцөл, хүчинтэй хоног, тайлбар. Подоны тоо/барьцаа болон НӨАТ-ыг тааж бөглөхгүй; барьцаагүй бол 0 гэж оруулна.
4. **Нэгж үнэд төлөх бүх татварыг тусгасан байна.** НӨАТ-ын багана нь тайлбар бөгөөд нэмэлт татвар автоматаар тооцохгүй. Нийт = м³ × нэгж үнэ − хөнгөлөлт + подоны барьцаа.
5. Нэг хэрэглэгчийн имэйл хаягийг эх хүсэлттэй нь тулган шалгаж P баганад **ТИЙМ** гэж бичнэ. Веб хүсэлтэд имэйл байхгүй бол хэрэглэгчээс зөв хаяг авч баталгаажуулах хүртэл илгээх боломжгүй.
6. **3. Урьдчилан харах** нь баталгаажаагүй загвар харуулна.
7. **4. Баталж PDF-ээр имэйлдэх** дээр нэр, хаяг, нийт дүнг шалгаж **Yes** дарна. Сервер `KH-Q-YYYY-000001` хэлбэрийн албан дугаар өгч, баталсан өгөгдлийг хадгалж, PDF үүсгээд зөвхөн тухайн хэрэглэгчид хавсралтаар илгээнэ. Google зөвшөөрөл өгсөн ажилтны хаягаас илгээгдэнэ; компанийн тусгай sender домайн хараахан тохируулаагүй.

### Хяналт ба алдаа
- Q–W баганад төлөв, албан дугаар, баталсан ажилтан/огноо, дотоод PDF холбоос, илгээсэн огноо, алдаа харагдана. Эдгээрийг гараар өөрчилсөн ч илгээх эрх үүсэхгүй; серверийн Drive бүртгэл нь үнэн зөв төлөв болно.
- `APPROVED`: баталсан, PDF эсвэл илгээхээс өмнөх шатанд зогссон. Өгөгдөл өөрчлөгдөөгүй бол цэсээр дахин оролдож болно; дугаар давхар үүсэхгүй.
- `SENDING` / `UNKNOWN`: илгээлтийн үр дүн тодорхойгүй. Давхар имэйлээс сэргийлж автоматаар дахин илгээхгүй. Илгээгчийн имэйл болон Apps Script Executions-ийг шалгасны дараа админ серверийн JSON бүртгэлийг шийдвэрлэнэ. Төлөвийг шууд `APPROVED` болгох нь давхар илгээж болзошгүй.
- `SENT`: MailApp илгээх хүсэлтийг амжилттай хүлээн авсан. Хүлээн авагчийн inbox-д хүрсэн эсвэл уншсаны баталгаа биш.
- Баталсан саналын үнэ, хаяг эсвэл бусад мэдээллийг дараа нь өөрчилбөл хуучин дугаараар илгээхгүй. Засварласан саналд шинэ хүсэлтийн дугаар ашиглана.
- PDF болон баталгаажуулалтын JSON файлууд тусдаа хувийн Drive хавтаст хадгалагдана; нийтийн холбоосын эрх нээхгүй. Хүснэгт болон эдгээр хавтсын хандалтыг эзэмшигч хянах шаардлагатай.
- Google-ийн имэйл квот дуусвал илгээхгүй. Автомат хугацааны trigger, шинэ хүсэлт бүрт автоматаар батлах ажиллагаа байхгүй.

## 2026.11.03 — Бодит холболт

Одоо байгаа bound Apps Script төсөлд шинэ код суулгаж, эзэмшигч Google эрхүүдийг зөвшөөрөн `setupSalesWorkflow` амжилттай ажилласан. **Албан үнийн санал** таб, **Үнийн санал** цэс болон хувийн Drive хавтаснууд үүссэн. Нийтийн lead receiver-ийн хуучин deployment/URL хэвээр, дотоод батлах цэс хадгалсан шинэ кодыг ашиглана.

`testSalesPdfNoEmail` Google дээр амжилттай ажиллаж, 51,423 byte бүхий нэг хуудас PDF үүсгэсэн. Монгол бичвэр, хөнгөлөлт, подоны барьцаа, нийт дүнгийн харагдацыг шалгасан. MailApp квотын шалгалт амжилттай. Энэ шалгалт имэйл илгээхгүй, албан дугаар зарцуулахгүй. Бодит имэйл хүргэлтийг туршаагүй.


## Борлуулалтын самбар

**Үнийн санал → Борлуулалтын самбар нээх** цэс нь зөвшөөрөгдсөн ажилтанд тусдаа цонх нээнэ. Сүүлийн 200 хүсэлтийг нэр, утас, дугаараар хайж, шинэ/хяналтад/илгээсэн төлөвөөр харна. Хүсэлт сонгоход draft бэлтгэж, харилцагч, үнэ, хөнгөлөлт, подоны барьцаа, НӨАТ-ын нөхцөлийг нэг формоор засна. Мэдээллээ шалгасан тэмдэглэгээ хийж **Хадгалж урьдчилан харах** дараад батална. Батлахад өмнөх албан дугаар/PDF/имэйл логикийг ашиглана.

100 × 240 × 600 мм (хэмжээсийн дараалал хамаарахгүй) блокийн баталгаажсан багтаамж **100 ш/подон**. Подон = ceil(ширхэг / 100). Шинэ draft-д энэ тоо автоматаар орно; засварлах үед **Тооцоог хэрэглэх** товчоор санал болгосон тоог хэрэглэнэ. Бусад хэмжээ, холимог бүтээгдэхүүнд багтаамж таахгүй. Нэг подоны барьцааны үнийг борлуулалт баталгаажуулж оруулна.

Самбарын бүх сервер үйлдэл allowlist эрх шалгана. Хоёр ажилтан зэрэг засвал өмнөх өгөгдлийн token зөрөхөд хадгалах/батлахыг зогсооно. Өөрчилсөн мэдээллийг дахин хадгалах хүртэл батлах товч идэвхжихгүй. Баталсан мэдээллийг самбараас засахгүй, илгээсэн саналыг дахин илгээхгүй. Энэ шинэчлэлтэд саналын шинэ хувилбарын дугаарлалт болон удирдлагын тусдаа хөнгөлөлтийн шат нэмээгүй.


## Борлуулалтын нэгж — м³

Вебсайтын үнэ, захиалга, урьдчилсан санал болон шинээр үүсэх албан PDF-д борлуулалтын хэмжээг зөвхөн м³-ээр харуулна. Тооцоолуур ханын талбай × зузаан × нөөцөөр эзлэхүүнийг шууд бодож, бүхэл ширхэгт тааруулж м³-ийг өсгөхгүй. Хөнгөлөлтийн өмнөх үнэ = м³ × нэг м³ үнэ. Подоны барьцааг тусад нь нэмнэ.

Sheet-ийн өмнөх багана, баталгаажуулалтын snapshot болон илгээсэн PDF-үүдийг хадгалсан. Ширхэгийн тоо нь зөвхөн дотоод савлагаа/подоны тооцооны мэдээлэл; ширхэгийн үнэ болон ширхэгээр борлуулах үйлдэл байхгүй.


## Лого, QR бүхий албан PDF загвар

Үнийн саналын нийлүүлэгчийн мэдээлэл серверт тогтмол **Хантайшир эко блок ХХК / РД:3267806 /** байна. Харилцагч эсвэл Sheets-ийн талбараас солих боломжгүй. Хавсаргасан жишгийн лого, ногоон/улбар шар өнгө, хүлээн авагч/нийлүүлэгчийн хайрцаг, бүтээгдэхүүний хүснэгт, тооцооны нийлбэр, Facebook QR, цахим баталгаажуулалтын хэсгийг ашиглана. Лого, QR нь код дотроо суулгагдсан тул гаднын зураг татах шаардлагагүй.

Зөв бүтэцтэй гадна/дотор ханын задаргааны м³ нь нийттэй тохирч байвал хоёр бүтээгдэхүүний мөрөөр харуулна. Тохирохгүй бол тоо таахгүйгээр баталсан нийт м³-ийг нэг мөрөөр гаргана. Мөрүүдийн нийт нь серверийн баталсан бүтээгдэхүүний үнэтэй таарна. Ширхэгийн үнэ, худалдааны ширхэг PDF-д харуулахгүй. Хөнгөлөлт, подоны барьцаа тусдаа, НӨАТ-ын тайлбар болон хүчинтэй хугацаа тодорхой байна.

Google дээрх имэйл илгээдэггүй smoke test амжилттай: нэг хуудас, лого/QR/өнгө/Монгол бичвэр бүрэн. Локал шалгалтад нийлүүлэгчийн нэр/РД, HTML escaping, м³ нэгж, задаргааны нийлбэр, өмнөх зөвшөөрөл/давхар илгээлтийн хамгаалалтууд орно. Шинээр үүсэх PDF-д шинэ загвар хэрэглэнэ; өмнө илгээсэн хадгалсан PDF баримтуудыг дахин үүсгэхгүй.


## Утасны хүсэлт бүртгэх

**2026.11.04 — Одоо ажиллаж буй bound Apps Script төсөлд суулгаж идэвхжүүлсэн. Бодит Sheets-ийн борлуулалтын самбарт товч болон маягт нээгдэж байгааг шалгасан. Хуурамч бүртгэл болон туршилтын имэйл үүсгээгүй.**

Самбарын **+ Утасны хүсэлт бүртгэх** товчоор нэр/байгууллага, утас, байршил, 300 эсвэл 200 мм блокийн хэмжээ, м³, байвал имэйл, тайлбарыг оруулна. Мэдээлэл бүртгэж эргэн холбогдох зөвшөөрлийг ажилтан баталгаажуулна. Бүртгэл нь **Веб үнийн хүсэлт** табд хадгалагдаж, **Албан үнийн санал** табд draft үүснэ. Вебсайт болон утасны хүсэлт нэг бүртгэлд төвлөрнө.

- Эх сурвалж O баганад **Утасны хүсэлт**, огноо A, хүсэлтийн дугаар B баганад хадгалагдана.
- R буюу 18-р баганад **Бүртгэсэн ажилтан** гэсэн шинэ талбар нэмнэ. Үүнийг зөвхөн баталгаажсан Google хэрэглэгчийн имэйлээр сервер бөглөнө. Хуучин багана/мөрүүдийг солихгүй. R баганад өөр мэдээлэл байвал дарж бичихгүй, бүртгэлийг зогсооно.
- Дахин оролдлогод нэг draftKey ашиглаж **KH-TEL-...** дугаар үүсгэнэ. Ижил хүсэлтийг давхар бүртгэхгүй; өөр ажилтны дугаарыг ашиглахыг хориглоно.
- Нэгж үнэ болон эх сурвалжийг сервер тогтооно. Албан үнийн өөрчлөлт, барьцаа, хөнгөлөлтийг дараагийн draft хяналтаар оруулна.
- Имэйлгүй утасны хүсэлтийг бүртгэж болно. PDF-ийг имэйлээр илгээхээс өмнө хаягийг оруулж баталгаажуулах шаардлагатай.
- Бүртгэх үйлдэл нь санал батлах, PDF илгээх үйлдэл биш. Батлах болон илгээсэн ажилтны өмнөх аудит хэвээр.
- Самбарт эх сурвалж, бүртгэсэн ажилтан харагдана. Нэмэлт ажилтан зөвшөөрөгдсөн Google хаягаараа нэвтэрнэ.

Шалгалт: `node google-apps-script/tests/PhoneEntry.test.cjs`. Бодит Google бүртгэл болон имэйлд нөлөөлөхгүйгээр эрх, validation, audit багана, давхар оролдлого, үндсэн веб формын нийцлийг шалгана.

## 2026.11.04 — Олон хэмжээтэй үнийн хүсэлт

Вебийн үнийн хүсэлт болон борлуулалтын самбарын утасны хүсэлтэд блокийн хэмжээг checkbox-оор олон сонгож, сонгосон хэмжээ тус бүрд м³ оруулна. Нийт м³ болон вебийн урьдчилсан үнэ автоматаар нийлнэ. Тооцоолуурын гадна/дотор ханын м³ нь сонголтуудад тусдаа дамжина; ижил зузаантай бол нэгтгэнэ.

Хэмжээ бүрийн задаргаа «Веб үнийн хүсэлт» табын H баганад хадгалагдаж, draft болон албан PDF-д тусдаа бүтээгдэхүүний мөрүүдээр орно. PDF-ийн задаргаа нийт м³-тэй зөрвөл баталсан нийт хэмжээг нэг мөрөөр харуулах өмнөх хамгаалалт хэвээр. Баталсан хуучин баримтуудыг дахин үүсгэхгүй.

Одоогоор батлагдсан каталог: 600 × 240 × 300 мм, 600 × 240 × 200 мм. Шинэ зузаан нэмэхдээ вебийн SIZES болон Code.gs-ийн KHANTAISHIR.blockThicknesses жагсаалтыг ижил шинэчилнэ. Урт/өндөр өөр бол зөвхөн зузааны жагсаалт өөрчлөхгүй, хэмжээсийн тооцоог хамт шинэчилнэ. Шинэ хэмжээс, үнэ, подоны багтаамжийг тааж оруулаагүй.

Бодит Apps Script-д хадгалж, борлуулалтын самбарт хоёр сонголт болон 10.25 + 4.75 = 15 м³ нийлбэрийг шалгасан. GitHub Pages-ийн бодит вебд хоёр сонголт, 15 м³ / 4,500,000₮ нийлбэр харагдсан. Одоо байгаа нийтийн receiver нь product/breakdown/volume/pieces талбаруудыг дэмждэг тул /exec URL, deployment өөрчлөх шаардлагагүй.

Шалгалтууд: QuoteApproval.test.cjs, PhoneEntry.test.cjs, MultiProduct.test.cjs. Бодит хүсэлтийн мөр, албан дугаар эсвэл туршилтын имэйл үүсгээгүй.

## 2026.11.04 — Үнийн саналын тусдаа цонх

Нүүр хуудсан дахь урт «Үнийн санал» болон «Блок тооцоолуур» хэсгүүдийг тусдаа native dialog дотор байрлуулав. Үндсэн цэсийн «Үнийн санал», header/hero-ийн товч нь хүсэлтийн табыг нээнэ. Тооцоолуурын холбоосууд болон «Яагаад AAC?» цонхны тооцоолох холбоос нь тооцоолуурын табыг нээнэ.

Цонх дотор «Үнийн санал авах», «Блок тооцоолох» гэсэн хоёр жижиг табтай. Таб солих, хааж дахин нээхэд маягтын мэдээлэл хадгалагдана. Тооцоолуурын «Үнийн санал авах» товч нь хэмжээ бүрийн м³-ийг хүсэлтийн табд шилжүүлнэ. Escape, хаах товч, гадна дэвсгэрээр хааж болно. Табын сум/Home/End keyboard удирдлага, role/aria-controls/aria-selected, focus trapping нь native dialog-оор дэмжигдэнэ.

Нийтийн хүсэлт илгээх болон PDF/Google Sheets backend өөрчлөгдөөгүй. Шалгалтаар гадна 30.24 м³ + дотор 6.3 м³ = 36.54 м³ / 10,962,000₮ зөв шилжиж, бөглөсөн нэр хадгалагдсан. Бодит имэйл/хүсэлт үүсгээгүй.

## 2026.11.04 — Нүүр хуудасны тооцоолуур ба борлуулалтын нөхцөл

Нүүр хуудсанд нэг тооцоолуур, «Үнийн санал» цонхны табд нэг тооцоолуур харагдана. Талбарын ID-ууд давхцахгүй; нэг тооцооллын зам, нэг төлөв ашиглаж хоёр харагдацыг синхрончилно. Нүүр хуудасны «Блок тооцоолох» болон footer-ийн холбоосууд home-calculator хэсэг рүү очно. Аль ч тооцоолуураас хэмжээ тус бүрийн м³-ийг хүсэлтийн табд шилжүүлнэ.

Борлуулалтын самбар:
- Нэг подоны барьцаа 250,000₮ тогтмол, засварлахгүй. Сервер хадгалах үед мөн 250000 гэж тогтооно. Нийт барьцаа = бодит подоны тоо × 250000. Подоны тоог баталгаажаагүй хэмжээнд таахгүй.
- Хөнгөлөлтийг 0–100%-иар оруулна. Сервер бүтээгдэхүүний үндсэн үнийн нийлбэрээс хувийг бодож төгрөгт бүхэлчилнэ. Хөнгөлөлт подоны барьцаанд үйлчлэхгүй. Одоо байгаа Sheet-ийн хөнгөлөлтийн мөнгөн дүнгийн багана хэвээр; PDF-д хувь болон мөнгөн дүн харагдана.
- НӨАТ-ын нөхцөл зөвхөн «Орсон», «Ороогүй». Энэ нь нөхцөлийн тайлбар; өмнөх нэгж үнэд төлөх татварыг тусгах зарчим хэвээр, нэмэлт татвар автоматаар нэмэхгүй.
- Хуучин draft шинэ нөхцөлд таарахгүй бол батлахын өмнө шинэ маягтаар хянаж хадгална. Баталсан/илгээсэн баримтын snapshot болон хуучин бодит нөхцөл өөрчлөгдөхгүй.

Бодит Apps Script-д суулгасан. Одоо байгаа draft-ийг зөвхөн нээж шинэ талбаруудыг шалгасан, хадгалаагүй/батлаагүй/имэйл илгээгээгүй. GitHub Pages-д нүүр хуудасны тооцоолуур байгааг шалгасан. Локал шалгалтад 3,000,000₮ × 5% = 150,000₮, 2 подон × 250000 = 500000₮, нийт 3,350,000₮; серверийн forced deposit, 100%-иас их хөнгөлөлт болон буруу НӨАТ-ын сонголтыг хориглох шалгалтууд амжилттай.

Самбарын дараагийн кодын шинэчлэлд энэ **тусдаа mobile deployment**-ийг Manage deployments → Edit → New version-оор шинэчилнэ. Зөвхөн Save нь аль хэдийн нийтэлсэн web app version-ийг шинэчлэхгүй.

Бодит утасны төхөөрөмж дээр шалгаагүй; хөтчийн жижиг дэлгэцийн харагдацыг шалгасан. Бодит үнийн хүсэлт, PDF эсвэл имэйл үүсгээгүй.
